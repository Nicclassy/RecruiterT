# RecruiterT
Job postings are very boring nowadays, and every man and his dog wants the same tech stack. 
This is especially true for internships and graduate roles. 
However, some people don't like the programming languages and frameworks that these companies require, and 
that's an unfortunate reality but something that must be accepted nonetheless. 

Based on an examination of many graduate roles and internships, RecruiterT is an app that on the surface
is appealing to recruiters. It uses a generic tech stack: a React-based frontend with TypeScript and Tailwind, 
a Spring Boot/Java backend, both chosen due to their popularity in the industry, and Hibernate, as many
jobs desire proficiency in an ORM. There are also other tools that don't fit neatly, such as Docker Compose to use 
a PostgreSQL database (both of which are very common tools), and JUnit for testing (this is yet to be done). 
There are a few other tools in this tech stack but they are not mentioned here because they aren't as 'generic'.

However, as it turns out, two other things are true: the tech stack has some unusual alterations, 
and the app may be useful for recruitees. Firstly, both Kotlin and Java are used for the backend.
This is not typical and quite redundant, but this was chosen as a way to make the 
programming experience a bit more enjoyable as Java can be frustrating sometimes. Secondly, Playwright is used. 
Playwright is not a typical tool in internships/graduate jobs, even if it appears later down the line.

## Why do I bother?
Candidates in the current job market are disadvantaged for not having a very specific set of skills. I happen to be one
of those people; I like Swift/SwiftUI and .NET but neither of these are desired in internships/graduate roles.
In making this project I intend to be a more 'appealing' candidate, though truth be told proficiency in these
tools has nothing to do with actual competency; it just checks boxes on a list. My hope is however that the right person
sees this and appreciates it for both satirical reasons and the integration of many different libraries/frameworks.
